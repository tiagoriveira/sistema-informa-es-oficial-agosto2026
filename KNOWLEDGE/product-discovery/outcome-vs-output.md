# Outcome vs. output

**Ideia central:** output é o que você entrega (uma feature); outcome é a mudança de
comportamento/métrica que essa entrega deveria causar. Medir sucesso por output esconde se o
problema foi resolvido.

## Explicação
Erro clássico: "lançamos 12 features este trimestre" não diz nada sobre se alguma delas
resolveu algo de verdade. É por isso que a árvore de [[continuous-discovery]] começa no
resultado desejado, não numa lista de features — partir de "vamos construir X" já pula a
pergunta "isso muda o quê, e como eu saberia que mudou?".

## Exemplo
App de agendamento pro salão: output é "lançar o app". Outcome é algo como "reduzir X% os
horários vagos por falta de aviso" — é esse número que decide se valeu a pena, não o
lançamento em si.
